# 一、leleby项目的总体定位

## 1.1 核心定位

leleby不是：

* 一个普通产品数据库
* 一个电商搜索平台
* 一个企业黄页
* 一个标准文档库

而是：

> **面向工业商业世界的开放语义基础设施 + 商业智能应用生态。**

核心目标：

通过：

* 工业产品本体
* 企业能力本体
* 标准语义模型
* 产品规格模型
* 要求与约束模型
* 符合性推理模型

建立机器可理解的工业知识体系。

最终支持：

* AI采购
* 企业AI商业名片
* 产品智能匹配
* 标准符合性验证
* 制造能力发现
* 工业知识推理

# 五、产品本体建模原则

## 5.1 产品主体优先

产品本体首先定义：

> 它是什么东西，由什么组成。

例如：

电动自行车：

```
ElectricBicycle

hasComponent:

Frame

Battery

Motor

Controller

Wheel

BrakeSystem

```

---

## 5.2 分类是属性条件函数

分类不是固定树。

分类本质：

```
Classification = Function(Property Values)

```

例如：

青年男子组：

```
Age >18
AND
Age <=45
AND
Gender = Male
```

因此：

```
Class

hasClassificationMethod

ClassificationCondition

```

---

采用：

RDF-star / RDF 1.2 Edge Annotation

表达：

```
:a  hasSubclass  :b

条件：

age>18 && age<=45 && gender='male'

```

# 六、Standard设计原则

## 6.1 Standard不是Ontology

这是重要结论。

Standard不是：

“一个产品类别定义”。

而是：

> 一个经过批准发布的规则集合。

因此：

标准应该作为独立Semantic Package。

例如：

```
IEC60598-1-2025.ttl
```

它包含：

```
Scope

Classification

StructureRequirement

PropertyRequirement

TestRequirement

SamplingRequirement

EvaluationRule

Reference

Approval

Version

```

# 八、哪些内容独立Ontology，哪些属于Standard？

## 8.1 应独立

因为高度复用：

---

## 产品基础概念

例如：

```
Product

Component

Property

```

---

## 测试方法

例如：

```
TemperatureMeasurement

TorqueMeasurement

ElectricalTest

```

原因：

同一个测试方法可以用于：

* 电机
* 灯具
* 电池

---

## 抽样方法

例如：

```
ISO2859 Sampling

```

适用于：

多个行业。

---

## 数据处理方法

例如：

```
Average

Deviation

ConfidenceInterval

```

---

## 通用判定逻辑

例如：

```
Value <= Limit

RangeCheck

ToleranceCheck

```

---

# 8.2 应保留在Standard Package

因为属于该标准法律范围：

---

## 标准对象范围

例如：

```
This standard applies to outdoor luminaires
```

---

## 分类规则

例如：

```
Class A motor

Power < 100W

```

---

## 特定要求

例如：

```
Motor temperature rise <=50K
```

---

## 特定抽样方案

例如：

某标准规定：

```
5个样品
允许1个偏差
```

---

## 特定判定规则

例如：

某标准：

```
全部关键指标必须满足
```

# 十一、标准版本有效性模型

不能简单：

```
new version > old version > invalid
```

必须：

版本图。

例如：

```
IEC60598


2012

 |

2020

 |

2025

```

三个版本可能同时有效。

原因：

产品生命周期。

---

产品实例：

```
ProductModel-A

designedAccordingTo

IEC60598:2012

```

永远保持这个事实。

---

如果型号升级：

```
ProductModel-A-v2

designedAccordingTo

IEC60598:2025

```

形成新的设计对象。

# 最终核心原则总结

1. **leleby不是数据库，而是工业语义基础设施。**

2. **Ontology定义世界结构，Standard定义约束规则。**

3. **产品主体先建模，再定义技术分类。**

4. **分类是属性条件函数，而不是固定树。**

5. **Standard必须作为独立、版本化、可追溯Semantic Package存在。**

6. **测试方法、测量方法、抽样方法应独立，因为它们高度复用。**

7. **标准版本必须采用类似Git的演化管理思想。**

8. **知识图谱表示当前状态，版本系统保存历史演化。**

9. **商业数据和公共语义必须分离。**

10. **PPM不是型号标准，而是能力单元标准。**

---

以上作为目前讨论后的 leleby 顶层设计基线。后续所有文档（Ontology Specification、Standard Specification、PPM白皮书、EIM规范等）都应该以此作为统一架构依据。
