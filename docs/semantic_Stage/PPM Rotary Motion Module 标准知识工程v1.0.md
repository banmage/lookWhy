## 1. 标准知识工程的战略定位

### 1.1 从“产品规划”到“标准知识工程”

在《PPM Rotary Motion Module 能力单元与制造生态规划 v1.1》中，我们已经完成了从“产品族规划”到“能力生态规划”的范式转换——明确了PPM的核心不是定义“一系列电机型号”，而是建立“一组由接口标准统一、由制造窗口约束、由语义模型描述、可被AI推理的可复用旋转动力能力单元”。

然而，能力生态规划的完成并不意味着标准本身已经存在。PPM标准不能凭空创造，而必须建立在**已有工业标准知识的基础之上**。这正是标准知识工程阶段的核心任务：

> **将分散在IEC、GB、JB等数百份标准文件中的工业知识，系统性地提取、结构化、语义化，转化为机器可读、可推理、可验证的PPM标准知识底座。**

### 1.2 标准语义提取的核心目标

| 目标 | 说明 |
|------|------|
| **知识提取** | 从标准文件中提取与旋转动力模块相关的术语、参数、约束、测试方法 |
| **语义建模** | 将提取的知识转化为OWL/RDF语义模型，纳入leleby Specification Ontology |
| **关系建立** | 建立标准之间、标准与能力族之间、标准与测试方法之间的可计算关系 |
| **规范生成** | 基于知识底座，生成《PPM Rotary Motion Module Specification v1.0》的完整骨架 |

### 1.3 标准知识工程与PPM各层级文档的关系

## 2. 国内外标准体系全景分析

### 2.1 标准分类框架

PPM Rotary Motion Module涉及的标准可按以下七层分类：

| 层级 | 标准类别 | 作用 | 优先级 |
|------|----------|------|--------|
| **L1** | 基础通用标准 | 定义电机的基本概念、定额、性能、安全 | P0 |
| **L2** | 尺寸接口标准 | 定义法兰、轴伸、安装尺寸 | P0 |
| **L3** | 性能测试标准 | 定义效率、振动、噪声、温升的测试方法 | P1 |
| **L4** | BLDC/永磁专项标准 | 针对BLDC和永磁电机的专用标准 | P0 |
| **L5** | 能效标准 | 定义能效等级和限定值 | P1 |
| **L6** | 安全与绝缘标准 | 定义安全要求和绝缘结构 | P1 |
| **L7** | 应用映射标准 | 定义特定应用（泵、风机等）对电机的需求 | P2 |

## 3. 标准语义提取方法论

### 3.1 语义提取的原则

**原则一：以能力为导向，而非以标准条款为导向**

提取的目标不是“把标准变成RDF”，而是“从标准中提取与PPM能力单元相关的约束和知识”。每个提取的知识单元都应能回答“这对PPM能力族意味着什么”。

**原则二：保持可追溯性**

每个提取的语义单元必须保留对原始标准条款的引用（标准号、条款号、版本），确保可追溯、可审计。

**原则三：分层提取**

按照leleby L1-L5模型分层组织提取的知识【战略白皮书v2.3 5.1】：

- **L1（外部知识层）** ：标准原文条款
- **L2（工程转化层）** ：标准条款的工程解释和适用条件
- **L3（产品定义层）** ：标准对PPM能力族的约束
- **L4（验证层）** ：标准定义的测试方法和判定准则

**原则四：建立标准间关系**

标准不是孤立的。PPM知识库必须建立标准之间的引用、约束、补充、冲突等关系。

### 3.2 语义提取的流程

```
┌─────────────────────────────────────────────────────────────┐
│  Step 1: 标准文本获取与预处理                                │
│  获取标准PDF/文档，进行OCR/文本提取，建立文档结构             │
├─────────────────────────────────────────────────────────────┤
│  Step 2: 章节解析与术语抽取                                  │
│  解析标准章节结构，抽取定义、术语、符号、缩略语               │
├─────────────────────────────────────────────────────────────┤
│  Step 3: 要求抽取（Requirement Extraction）                 │
│  识别标准中的"shall"、"should"、"may"等要求性语句            │
│  提取为结构化的Requirement对象                              │
├─────────────────────────────────────────────────────────────┤
│  Step 4: 参数与约束抽取                                     │
│  识别数值参数、范围、条件、单位、公差                        │
│  提取为结构化的Parameter + Constraint对象                   │
├─────────────────────────────────────────────────────────────┤
│  Step 5: 测试方法抽取                                       │
│  识别测试条件、测试设备、测试步骤、判定准则                  │
│  提取为结构化的TestMethod对象                               │
├─────────────────────────────────────────────────────────────┤
│  Step 6: 关系建立                                           │
│  建立标准间、条款间、要求与测试间的引用/约束关系              │
├─────────────────────────────────────────────────────────────┤
│  Step 7: 语义化编码                                         │
│  将提取的结构化知识转化为OWL/RDF格式                         │
│  纳入leleby Specification Ontology                          │
└─────────────────────────────────────────────────────────────┘
```

### 3.3 标准语义模型框架

每个提取的标准条款将转化为以下语义模型：

```json
{
  "source": {
    "standardId": "GB/T 755-2025",
    "clause": "5.6.3",
    "version": "2025"
  },
  "requirementId": "REQ-MOT-001",
  "requirementType": "PerformanceRequirement",
  "subject": "RotaryMotor",
  "property": "RatedVoltage",
  "constraint": {
    "operator": "shall",
    "value": "specified_by_manufacturer",
    "condition": "rated_operation"
  },
  "semanticMapping": {
    "ontologyClass": "ppm:RatedVoltageConstraint",
    "property": "leleby:hasVoltageRating"
  },
  "relatedRequirements": ["REQ-MOT-002", "REQ-MOT-003"]

```

### 3.4 标准间关系建模

PPM知识库需建立以下标准关系类型：

| 关系类型 | 说明 | 示例 |
|----------|------|------|
| `conformsTo` | 标准遵循上级标准 | GB/T 755-2025 conformsTo IEC 60034-1:2022 |
| `references` | 标准引用另一标准 | GB/T 14711-2025 references GB/T 755-2025 |

| `constrains` | 标准约束能力族 | GB 30253-2024 constrains PPM-RM-Power |
