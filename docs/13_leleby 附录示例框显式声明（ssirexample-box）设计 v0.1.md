## 1. 背景与问题

### 1.1 现象（GB_T_20001.5-2017 附录 A）

附录 A（资料性）规范标准编写示例中，**示例 1 的方框错误地吞并了**：

1. 表2 之后的一段附录正文（「示例2示出了以制成品为标准化对象的产品规范标准……」——
   它其实是 A.1 对 示例2 的引导说明，应排在方框外）；
2. 「示例2：」题注；
3. 示例2 的全部内容（手持式金属探测器技术规范，含其自身的表）。

即一个黑色线框覆盖了本应是"框-正文-框"三个部分的内容。

### 1.2 根因（三层定位：builder/渲染启发式链）

方框边界目前由两级**自动猜测**共同决定，任何一级被抽取噪声破坏就串框：

1. **builder `_mark_annex_examples`（builder.py L302-363）**：按"附录/附录小节内是否处于
   示例活动态"给节点打 `exampleContent: true`。其状态机**只把带编号的 A.x 小节标题视为
   示例块结束**，不把下一个「示例N：」题注视为结束（题注被视为无编号内容继续激活）。
   实测：20001.5-2017 中 示例1、引导段、示例2（题注+内容）落在同一条连续激活区间
   （SSIR root[18]~root[25] 全部 `exampleContent=true`）。
2. **树形错位放大**：canonical 里「## 示例2：」的线性位置是对的，但 builder 对示例题注
   的特殊层级处理把它（以及引导段）归进了示例1 内部 7.2 条款的子树，进一步掩盖了
   "新示例开始"的边界信号。
3. **渲染端（pdf_renderer 与 docx_renderer 各一份）**：把"连续的 exampleContent 兄弟"
   整段包进 `_example_box`（一个框），边界完全取决于兄弟链在哪断开 → 上述区间被渲染成
   单个大框。

结论：**canonical（线性文本）顺序正确、边界正确；缺的是把"边界"显式固化下来**。

### 1.3 方案动因

与其继续修补两处启发式（GEN-093 修过"文后要素误标"、本轮又出现"多示例串框"，说明
此类启发式持续易碎），不如让 **canonical 显式声明框边界**，使：

- 边界只取决于人工可编辑的权威基线（canonical 的定位本就是"唯一人工可编辑"）；
- builder 的示例激活状态机退化为"按显式标记执行"，渲染端退化为"按显式分组开框"；
- 将来 MinerU 抽取层如何摆放示例题注/正文都不再影响框边界。

用户已确认：语法采用**注释指令式**（与现有 `<!-- ssir:table ... -->` 同风格），
标记成为**示例框的唯一正式声明方式**，并迁移现有语料。

## 2. 目标 / 非目标

### 2.1 目标

1. canonical 新增成对显式标记，声明"某段内容放进一个黑色/浅色示例框"；
2. parser 识别并校验标记；builder 依据标记生成示例分组（替换 `_mark_annex_examples`
   的"连续激活"推断）；pdf/docx 双渲染按显式分组各开各的框；
3. 20001.5-2017 附录 A 渲染为「示例1 框 → 引导正文 → 示例2 框」；
4. roundtrip 等价保持（render.md 确定性重放标记）；
5. 旧数据迁移 + 回归夹具 + docs/07（CSM 规范）/ docs/12（知识库）沉淀。

### 2.2 非目标

- 不改 canonical 里示例正文的**文字与顺序**（结构错位问题仅用标记表达边界，必要时做
  最小结构校正并说明依据）；
- 不恢复/保留"自动打包"作为并行途径（见 §4 兼容策略）；
- 不在本次设计里处理 PDF 渲染的其它版面问题（列宽等已单独修复）。

## 3. 语法设计

### 3.1 标记形态（注释指令式）

```markdown
## 示例 1：
<!-- ssir:example-box -->
## 1 000 kV 变电站监控系统 技术规范
## 5 系统结构
……
<!-- ssir:/example-box -->

示例2示出了以制成品为标准化对象的产品规范标准……

## 示例2：
<!-- ssir:example-box style="frame" -->
## 手持式金属探测器通用技术规范
……
<!-- ssir:/example-box -->
```

- 开标记：`<!-- ssir:example-box -->`，可选 `style="frame|shaded"`（缺省 frame，
  渲染 profile 仍可整体默认覆盖；`frame`=黑色细实线框，`shaded`=浅色底，与现
  `exampleStyle` 语义一致）；
- 关标记：`<!-- ssir:/example-box -->`；
- **框外题注**（「示例N：」）继续用普通标题行写在开标记之前，不进框（与现状一致，
  样式 `example-label`）；
- 框内容从开标记后的第一个块开始，到关标记前的最后一个块为止，**逐块**（paragraph/
  table/figure/formula/heading/note/list…），不要求内容本身构成一个完整章节；
- 标记是**行级独占**指令行（与 `DIRECTIVE_RE` 匹配），不允许与正文混排在一行。

### 3.2 合法位置与粒度（关键设计决策 D1）

示例框内容目前在 SSIR/渲染流中落在两类粒度：

- **整节点级**：框包住若干完整同级结构节点（最常见）；
- **节点内容中途**：如 20001.5-2017 引导段是 7.2 条款的**尾部内容元素**，框必须在
  表2 与引导段之间关闭（7.2 条款本身"半在框内、半在框外"）。

设计决策 D1（**建议**）：标记允许出现在**任意两个相邻块之间**（含同一条款的正文内容
元素序列中间），即"按流式块边界开合"。理由：20001.5-2017 的真实数据需要此粒度，
否则必须重排 canonical（把引导段移出 7.2 并另配结构），数据手术面更大、且违背
"canonical 线性顺序本就正确"的事实。实现上把框视为**渲染流上的开合事件**而非
"节点属性"，代价是渲染端要支持"一个节点的内容被切分进/出框"（§6.3/6.4）。

备选（D1-B）：只允许整节点级（标记必须位于同级结构节点之间）。更简单，但需要把
20001.5-2017 的引导段/示例2 题注从 7.2 子树移到 A.1 级并安排一个正文容器——canonical
改动超出"插标记"，不推荐。

### 3.3 其它语法规则

- 配对与嵌套：示例框**不得嵌套**（parser 对嵌套开标记报错）；未配对（缺开或缺关）按
  CSM 错误/警告记录并给出行号（新 issue 码建议 `CSM-STRUCT-006`，登记 docs/12 §5.3）；
- 框内允许出现 `ssir:table / table-merge / figure / formula` 等既有指令，互不影响；
- 示例框标记**不影响文本内容与结构**，只表达"演示分组/版面"，因此 normalize 应原样
  保留（如同既有 directive 的保留策略），validate/roundtrip 不受内容层影响。

## 4. 数据模型（SSIR）

现状：`exampleContent: true` 只是节点布尔标记，渲染端据此做连续打包。

建议（D2）：

1. SSIR 结构节点与内容元素新增可选整数字段 **`exampleBox`**（1..n），取值含义：
   "渲染/导出时该节点（或该内容元素）属于第 n 个示例框"；无值 = 不在任何框内；
   （保留 `exampleContent` 布尔便于兼容旧字段/检查；或实施期直接以 `exampleBox` 取代，
    按 D4 裁定。）
2. canonical 开/关标记解析后：
   - 开标记 → 之后遇到的每个"入框块"（节点或内容元素）得到当前框序号；跨节点递增；
   - 关标记 → 回到框外状态；同一文档可多次开合（示例1、示例2 …），框序号单调递增。
3. schema：`ssir.schema.json` 结构节点/内容元素定义登记 `exampleBox`（可选 int ≥1，
   不设 additionalProperties 冲突）；规则文件/source 注释同步（GBT-B11/GBT-X05 执行侧）。

### 4.1 标记 → SSIR 归属的解析原则

框的开合在**块流**上推进；同一条款的部分内容入框、部分内容在框外时，归属按块边界
落到各自的**内容元素**上（节点级的 `exampleBox` 是其全部内容元素取值的"代表值"，
用于校验：若节点内容元素取值不一致，节点本身记为无代表值，渲染端逐元素开合处理）。

> 该原则是 D1 在数据模型层的自然延伸；若评审选择 D1-B（整节点级），则此条简化为
> 节点级取值即可。

## 6. 各层改动清单

### 6.1 parser.py（CSM → AST）

- `DIRECTIVE_RE` 已是 `^<!--\s*ssir:([a-z-]+)...-->$`，`example-box` 与 `example-box/`
  会被识别为 ssir 指令但目前落到"unsupported → unknown content + warning"分支：
  改为显式登记 `example-box`（开）与 `/example-box`（关）两种指令；
- 块流解析时记录开/关事件的位置（行号），并携带于其后块对象（Block）上；
- 配对/嵌套校验（见 §3.3）：缺配对/嵌套 → 错误（记 issue 码）；
- 段落折行/示例题注提升（CSM-OCR-008 相关）不得把标记行并入文本；
- `validate`（宽容/严格）在报告里体现配对警告；canonical 无标记的文档行为与现在一致。

### 6.2 builder.py（AST → SSIR）

- `_mark_annex_examples` **改为显式执行**：
  - canonical 有标记 → 完全按标记推进 `exampleBox` 归属（状态机只在"无标记"时无需
    工作，见兼容策略 §7——建议无标记文档不进入示例标注/保持历史行为仅作过渡验证，
    最终目标：语料全部显式后删除连续激活推断分支）；
  - 取消"下一个 A.x 小节才结束示例块"的隐式依赖；`示例N：` 题注节点的归属：题注本身
    **不进框**（`exampleBox` 空），其后续兄弟/内容按标记入框；
- 节点/内容元素写 `exampleBox`（schema 登记见 §4）。

### 6.3 pdf_renderer.py

- 示例框打包从"连续 exampleContent 兄弟"改为**按 `exampleBox` 分组**：
  - 组 = 具有相同 `exampleBox` 序号的连续渲染单元（节点**及节点内的内容元素**）；
  - 渲染流维护"当前是否在框内"状态：入框块追加进 pending 列表，遇到框外块或文档
    结束/下一组开始处把 pending 交给 `_example_box`（沿既有行拆/跨页逻辑）；
  - 「示例N：」题注（框外节点）照旧渲染在框上方；
  - 样式：`exampleBox` 组样式来自对应开标记的 `style`（SSIR 需要保存，见 §4.1/D3）；
- 几何宽度修复（本会话已落地的 `content_width` 传递）保持不变——框内容物仍是同一批
  flowables，只是分组边界来源改变；
- 若 D1-B 通过则渲染端改动减半（仍按节点分组）。

### 6.4 docx_renderer.py

- `_example_group`/`_example_node` 同一原则：按 `exampleBox` 分组逐框输出
  （STYLE_EXAMPLE 浅灰底段落组），不再依赖连续 exampleContent 兄弟。

### 6.5 csm_renderer.py（SSIR → render.md）

- 按节点/内容元素的 `exampleBox` 变化点**确定性重放** `<!-- ssir:example-box -->` /
  `<!-- ssir:/example-box -->` 标记行（顺序与 canonical 一致）；
- render.md 重 parse 后（verify）得到与 SSIR 相同的 `exampleBox` 归属 → roundtrip
  一致（D4：比较口径确认——若 roundtrip 比较含该字段，则此重放是等价前提）。

### 6.6 roundtrip / validation / compliance

- `validation.py`：节点/内容元素 `exampleBox` 与 `exampleContent` 一致性（可选 must/
  warning）；框序号从 1 连续递增校验；
- `roundtrip.py`：确认比较是否覆盖 `exampleBox`（D4）；建议**覆盖**并借 render.md 重放
  保持一致（更强的不变量：框边界 roundtrip 无损）；
- `compliance.py`：暂不新增合规检查（示例框属"编写规则标准附录示例"的版面，非内容
  合规）；若 GBT-B11 需要可加 should。

### 6.7 其它

- `docx_importer`/`docx_renderer` 的 docx→CSM 路径如需支持（未来 docx 输入示例框），
  记录为后续项，不阻塞本次；
- `mineru_full_standard`/merge 侧：新抽取文档的 canonical 若含多示例，暂由迁移脚本
  统一处理；抽取层不自作主张生成标记（避免再次引入猜测）。

## 7. 兼容与数据迁移（先规则后数据，AGENTS §0.4）

**兼容策略（已确认）**：显式标记成为唯一正式途径；不保留"自动连续打包"作为并行分支
（并行 = 双份逻辑 + 串框风险面保留）。过渡期（迁移未完成前）构建/渲染对**无标记文档**
的行为：先与现状一致（维持旧标注），全部语料迁移完成后删除旧推断分支——顺序上先
新后旧，避免一次性断裂。

**迁移工作流**（不手工静默改 canonical）：

1. 规则/代码先行：语法 + parser/builder/渲染 + 夹具 + docs 全部落地并通过（§8.2）；
2. 写确定性辅助脚本（如 `tools/annotate_example_boxes.py`）：
   - 输入 corpus 各 canonical；
   - 对含附录示例的文档（首批：GB_T_20001.5-2017；随后扫描 20001.6/20001.10/1.1-2020
     等）定位每个「示例N：」边界，输出"建议插入位置 + 当前被串入框的疑似越界块"
     （如 20001.5 的引导段），**人工确认后**落标记；必要时同时输出最小结构校正建议
     （把误嵌在 7.2 子树的「示例2：」题注/引导段提升到框外位置），校正同样走
     "规则→脚本→确认"，且逐条记录依据；
3. 每份迁移后：重 parse 幂等（跑两遍结果一致）、roundtrip passed、渲染几何抽查
   （框边界位置）、canonical 的 sha256 变化仅来自标记/最小结构校正，diff 逐条可见。

## 10. 风险与开放问题
