# leleby Canonical SSIR Markdown Format Specification v0.2

> **状态**：Draft | **版本**：1.1 | **日期**：2026-08-17
>
> **适用范围**：本规范定义 `Canonical SSIR Markdown`（简称 **CSM**）。CSM 是 `PDF -> MinerU -> CSM -> SSIR` 链路的版本化中间文档，也是用户直接提交给 `CSM -> SSIR` 解析器的输入格式。用户原始 Markdown 经宽容校验和基础纠错后冻结为 `Canonical` CSM；`Canonical` 是后续 SSIR 回环验证的唯一输入基线。
>
> **规范性参考**：GB/T 1.1-2020，特别是文件要素、章/条/段/列项层次、附录、图、表、数学公式、示例和注的编排规则；产品标准还应符合 GB/T 20001.10-2014。

## 1. 目标和边界

CSM 的目标是让同一个 `CSMParser` 接受两类输入：

```text
PDF -> MinerU -> Extraction IR Normalizer -> CSM -> CSMParser -> SSIR
用户原始 Markdown -> CSM Validator/Normalizer -> Canonical CSM -> CSMParser -> SSIR
```

CSM 是 SSIR 的可读、可编辑交换格式，但不是 SSIR JSON 的文本化替代。它必须保留足以构建结构、内容、文本、表格、图、公式、列表、注和引用的信息；无法表达或无法识别的内容必须显式保留，不能静默删除。

以下内容不属于 CSM 正文格式的职责：

- PDF 版式、字体、页眉页脚和分页；
- PDF 坐标、OCR 置信度、MinerU 原始 block ID 等机器溯源信息；
- 完整的 SSIR JSON ID、处理运行记录和质量评估。

需要 PDF 级溯源时，CSM 必须配套使用第 10 节定义的 provenance sidecar。没有 sidecar 的用户 CSM 仍可生成 SSIR，但默认只能声明为 Markdown 级可追溯，不能声明为 PDF Level 3 溯源。

## 2. 一致性等级

| 等级 | 输入要求 | 可生成内容 |
|------|----------|------------|
| CSM-Core | UTF-8 CSM 文件通过第 11 节校验 | L0-L3 SSIR，含 Markdown 行/列和 AST block 溯源；不含 PDF 级锚点 |
| CSM-Traceable | CSM-Core + 合法 provenance sidecar | L0-L3 SSIR，含 PDF 页面/bbox 或其他原始来源锚点 |
| CSM-Full | CSM-Traceable + 图像资产、表格合并元数据、公式原文 | 可完整覆盖 L0-L3 内容对象 |

`PDF -> MinerU` 路径至少应产出 CSM-Traceable。用户直接提交 CSM 时，sidecar 是可选的；若未提交，系统生成 Markdown 行号、列号和 AST block ID 作为最小溯源。

## 3. 基本约定

### 3.1 文件和编码

- 扩展名必须为 `.md`，编码必须为 UTF-8（无 BOM），换行必须为 LF。
- 每个文件只表示一个标准化文件；不允许将多个独立标准拼接到一个 CSM 文件中。
- 使用 CommonMark 基础语法和 GFM 表格、删除线、任务列表扩展；禁止依赖浏览器专有 Markdown 行为。
- 正文不使用原始 HTML。唯一允许的 HTML 是本规范定义的 `<!-- ssir:... -->` 机器注释，以及 GFM 表格单元格内表示原始换行的 `<br>`。
- 文本中的空白、全半角标点、数值、单位、比较运算符、规范性动词和引用文本均为源内容，不得因准备 CSM 而擅自改写。

### 3.2 机器注释

机器注释只用于稳定 ID、复杂表格合并信息、无法内嵌表达的内容和来源映射。其通用形式如下：

```markdown
<!-- ssir:<directive> key="value" key2="value2" -->
```

- 属性名使用 ASCII kebab-case；属性值使用双引号并转义 `"` 和 `\\`。
- 用户可以省略普通段落、标题和列表的 `block-id` 注释，导入器会按 AST 位置生成；MinerU 生成的 CSM 应保留它们。
- `id` 在一份 CSM 中必须唯一，推荐形式为 `h-001`、`p-001`、`tbl-001`、`fig-001`、`fm-001`、`unk-001`。
- 除本规范列出的指令外，解析器必须将注释原文保留为 `UnknownContent`，不能直接丢弃。

### 3.3 空行和顺序

- 相邻的块级元素之间必须恰好有一个空行，代码块和表格前后也必须有一个空行。
- 不得为了视觉排版拆分同一段落；同一段落的软换行会被规范化为一个空格。
- 文档、章、条、段、列表项、表格行和图/公式/注的出现顺序就是 SSIR 的 `sortOrder`。

### 3.4 规范符合性与导入容错

本规范定义的是**目标 CSM**；用户上传文件的默认处理是“尽量保留并转换”，不是把 GB/T 1.1 或 GB/T 20001.10 的全部建议性、可选或条件性组成部分误判为不可导入错误。导入器有两种模式：

| 模式 | 用途 | 对可修复问题的行为 |
|------|------|--------------------|
| 默认宽容导入 | 用户上传、批量迁移 | 进行无语义损失修复或原样保留，生成 SSIR 和转换报告，质量状态为 `partial` |
| `--strict` 一致性检查 | CSM 生产端、CI、Golden 数据集 | 将任何警告提升为失败，不生成输出 |

自动修复仅限机器元数据和格式边界，例如移除 BOM、规范化换行、补齐缺少的元数据默认值、为短表格行补空尾单元格、为缺少 ID 的对象生成稳定 ID。导入器绝不自动改写正文、标准编号原文、技术数值、单位、比较符、公式或规范性动词。

完成宽容导入后，系统以修复后的内存 AST 写出 UTF-8/LF 的 `Canonical`。`Canonical` 的转换报告必须保留原始输入 SHA-256 和每项修复；之后的 `Canonical -> SSIR -> Render.md -> Verify` 只比较 SSIR 与 Verify，不以未校正的原始 Markdown 作为等价基线。

## 4. YAML Front Matter

CSM 文件必须从 YAML front matter 开始。仅允许使用下表字段；未知字段必须放入 `extensions` 对象，避免同名私有字段破坏兼容性。

```yaml
---
csm-version: "1.0"
document-type: standard
document-identifier: "Q/EXAMPLE 001-2026"
standard-number: "Q/EXAMPLE 001-2026"
title: "永磁直流无刷电动机"
language: zh-CN
source:
  mode: user-markdown
  original-file-name: "Q_EXAMPLE_001-2026.md"
  provenance: none
rendering-profile: GB_T_1.1-2020
extensions: {}
---
```

| 字段 | 必填 | 规则 |
|------|------|------|
| `csm-version` | 是 | 当前固定为字符串 `"1.0"` |
| `document-type` | 是 | `standard`、`guidance`、`technical-report`、`contract`、`other` 之一 |
| `document-identifier` | 是 | 文件业务标识；标准通常与标准号相同 |
| `standard-number` | 条件必填 | `document-type=standard` 时必填，保留原始标准号写法 |
| `title` | 是 | 文件中文或原始标题；不得包含 Markdown 标记 |
| `title-en` | 否 | 英文标题；无值时省略，不使用 `null` |
| `language` | 是 | BCP 47 语言标记；中文通常为 `zh-CN` |
| `source.mode` | 是 | `mineru-pdf` 或 `user-markdown` |
| `source.original-file-name` | 否 | 原始 PDF 或用户文件名 |
| `source.original-file-sha256` | 否 | 原始文件 SHA-256 小写十六进制值 |
| `source.provenance` | 是 | `sidecar` 或 `none` |
| `rendering-profile` | 否 | 如 `GB_T_1.1-2020`；仅记录期望规范化配置 |
| `extensions` | 是 | 空对象或命名空间化的扩展对象 |

禁止将发布日期、实施日期、发布机构、起草单位等标准内容只放入 front matter。它们必须同时出现在相应的正文要素中，以保证在没有 YAML 解析器的情况下仍可审阅。

## 5. 文档总体结构

CSM 采用 GB/T 1.1 的要素顺序。可选要素可省略，但已出现的要素不得调整顺序。

```text
YAML front matter
# 文件名称

## 目次                         (可选，资料性)
## 前言                         (标准文件必备)
## 引言                         (可选)
## 1 范围                       (正文起点)
## 2 规范性引用文件             (按需)
## 3 术语和定义                 (按需)
## 4 ...                        (正文技术要素，连续编号)
## 附录 A（规范性） 标题         (按需)
## 附录 B（资料性） 标题         (按需)
## 参考文献                     (按需)
```

`#` 只允许出现一次，且内容必须与 front matter 的 `title` 完全一致（允许 Markdown 转义差异）。`##` 既用于前置/后置要素，也用于正文的章；解析器通过标题是否以连续的阿拉伯数字或附录标识开头判定其类型。

### 5.1 前置和后置要素

| 要素 | 标题写法 | 要求 |
|------|----------|------|
| 目次 | `## 目次` | 可选；若提供仅作资料性文本，不驱动结构树 |
| 前言 | `## 前言` | 标准文件必备；内容保持原文，不编号 |
| 引言 | `## 引言` | 可选；内容保持原文，不编号 |
| 参考文献 | `## 参考文献` | 可选；使用无序列表，每项为一条原始参考文献 |
| 索引 | `## 索引` | 可选；保留为 `UnknownContent` 或列表，Phase 1 不进行术语推理 |

### 5.2 章、条和段

GB/T 1.1 要求章编号从范围开始连续，条使用下脚点分隔的阿拉伯数字，段不编号。CSM 用标题深度表达条的层次：

| 逻辑层次 | CSM 写法 | 示例 |
|---------|----------|------|
| 文件名称 | `# <title>` | `# 永磁直流无刷电动机` |
| 章 | `## <N> <title>` | `## 1 范围` |
| 第 1 层条 | `### <N.N> [title]` | `### 4.1 环境条件` |
| 第 2 层条 | `#### <N.N.N> [title]` | `#### 4.1.1 海拔` |
| 第 3 层条 | `##### <N.N.N.N> [title]` | `##### 4.1.1.1` |
| 第 4 层条 | `###### <N.N.N.N.N> [title]` | `###### 4.1.1.1.1` |
| 段 | 普通段落 | 不得人为添加段编号 |

规则如下：

- 标题编号必须与其父标题前缀一致，例如 `4.2` 只能位于 `4` 下，`4.2.1` 只能位于 `4.2` 下。
- 章必须从 `1` 开始，直至附录前连续；不允许跳号。
- 标题可在编号后省略标题文本，以表达 GB/T 1.1 允许的无标题条，例如 `#### 6.1.1`；此时该标题后的第一个段落就是条文首段。
- 同一父级下的同层条有标题或无标题的表达方式必须一致。无编号的段使用普通段落，不得伪造条编号。
- 标题中的编号、标题文本与规范性动词均为语义内容，不得在 CSM 规范化时改写。
- 可使用 `<!-- ssir:block id="h-001" -->` 标记标题，但注释必须紧邻在标题前一行。

### 5.3 附录

附录标题必须使用下列形式，附录字母连续且不得与正文数字章节混用：

```markdown
## 附录 A（规范性） 试验条件
## 附录 B（资料性） 计算示例
```

- `规范性` 和 `资料性` 为必填状态词；不确定时使用 `（未判定）`，导入器应产生警告。
- 附录内部的第一级条使用 `### A.1 <title>`，后续层级依次为 `#### A.1.1`、`##### A.1.1.1`。
- 附录中的图、表和公式编号必须保留其原文；若采用 `A.1` 形式，不得改为正文编号。

### 5.4 产品标准配置文件（GB/T 20001.10）

当 `document-type: standard` 且文件属于有形产品标准时，建议在 `extensions` 中声明产品标准配置：

```yaml
extensions:
  standard-profile: product
  profile-rules: ["GB_T_1.1-2020", "GB_T_20001.10-2014"]
```

产品标准配置不改变 CSM 的通用语法，但导入器必须额外检查：

- `## 1 范围` 明确产品、涉及的技术内容、预期用途和适用界限；范围应为陈述型条款，不写“应”“宜”等要求型语句。
- 标准号应按 `标准代号 顺序号—年份` 的形式著录（例如 `Q/EXAMPLE 001—2026`）；发现 ASCII 连字符、缺失年份或顺序号异常时，导入器应提示。若只是在元数据中规范化分隔符，应在 `quality-notices` 中记录原始写法。
- `## 4` 以后至少有一个技术要求章；产品名称可以单独作为标准名称的前提是标准包含适用的分类/标记、技术要求、试验方法、检验规则、标志/标签/随行文件等要素，否则应在名称中使用“技术规范”或“规范”等补充要素，或在 `quality-notices` 中提示人工确认。
- 每项可证实的技术要求应给出量值、限值或明确的判定条件，并能在试验方法中找到对应的验证路径；“适当”“正常”“符合要求”等无判定依据的词语必须产生质量警告。
- 要求表格宜使用“编号、特性、特性值、试验方法”等列，并在正文中明确提及表格；不得把合同、索赔、担保、费用结算或法律法规要求写成产品技术要求。
- 试验方法应优先引用适用的现行方法标准；自编方法应至少说明试样/样品、设备或条件、步骤和结果表述。存在多种方法时，应标明仲裁方法。
- 检验规则（如有）应说明适用范围、检验类型、组批/抽样、检验项目和判定规则；不得以质量管理体系标准作为产品符合性的条件。
- 标志、标签和随行文件应规定标识内容、表示方法和位置（适用时），但不得把认证/符合性标志本身写成产品标准要求。包装、运输和贮存应单独可定位。
- 安全、健康、环境和资源合理利用要求不得使用“由供方自行确定”替代必要的限值；供方确定的性能值必须规定测量方法及其载体（铭牌、标签或随行文件）。

`extensions.quality-notices` 是保留原始用户文件时的提示容器。提示不得修改正文语义，格式如下：

```yaml
extensions:
  standard-profile: product
  profile-rules: ["GB_T_1.1-2020", "GB_T_20001.10-2014"]
  quality-notices:
    - code: GB20001-10-6.5.4
      severity: warning
      message: "第6.5.4条缺少可核验的量值或试验方法，请人工确认。"
```

## 6. 内容块格式

### 6.1 普通段落、强调和引用

普通段落使用连续文本。仅当源文档确实包含强调时使用 `**粗体**`、`*斜体*` 或 `~~删除线~~`；这些标记本身是表现信息，不应被当作规范性文本的一部分。

```markdown
电动机应符合本文件的要求，并按照经规定程序批准的图样及技术文件制造。

下列文件中的内容通过文中的规范性引用而构成本文件必不可少的条款。
```

引用原文使用 GFM block quote；不要用引用语法模拟普通缩进段落：

```markdown
> 本文件的某些内容可能涉及专利。
```

### 6.2 列项和分项

列项必须保留原始标记类型和层级。无序列项使用 `-`，有序列项使用实际编号并保留 `a)`、`1)` 等形式：

```markdown
下列条件应同时满足：

- 环境温度：+15 ℃ 至 +35 ℃；
- 相对湿度：45 % 至 75 %。

a) 额定电压；
b) 额定转速。
```

标记后允许无空格：OCR 常把 GB/T 1.1 的破折号 `——` 压成单个 `-` 或 `—` 并丢失后方空格（如 `-电动机应…`），导入器仍按列项识别，marker 取整段破折号。列表项之间的空行不打断列项（CommonMark loose list），MinerU 常用空行分隔各条。列表编号括号统一为全角（`a)` → `a）`，GBT-C19）——半角/全角混用会使渲染出的文字与标记视觉间隔不统一；正文条号（`4.6.1电动机` → `4.6.1 电动机`）统一在编号后留一个空格（GBT-B02）。字形混淆（OCR 把 `l）` 读成 `1）`、把 `1` 读成 `l/I`、把 `0` 读成 `O`）在解析时按多数派上下文纠正：字母多数列表中唯一的数字 `1）` 改回 `l）`，数字多数列表中的 `l)/I)/O)` 改回 `1)/1)/0)`，并记录 CSM-OCR-001（repaired）。表格单元格中"不适用"的一字线 `—` 被 OCR 误读为 `一`/`二`/`/`/`－` 等时，单独成格的这些符号统一归一为 `—`（GBT-C17）。表脚注（GB/T 1.1：被注释内容后跟上角标字母，表下方以 "a 说明" 列出）的引用标记被 OCR 丢失时，导入器从脚注行反推补回被引用单元格（说明文本包含其完整内容的最长单元格），找不到匹配则不猜测（GBT-C18）；渲染时表格中的脚注标记（行首 "a "、汉字后紧跟的小写字母）统一渲染为上角标，排除单位字母（m/s/g/l/t/h）防误伤。渲染 PDF 时按 GB/T 1.1-2020 6.6.3 统一：第一层次列项用 `——` 或 `a）`，空两个汉字起排、回行对齐第 5 汉字；第二层次列项用 `·` 或 `1）`，空四个汉字起排、回行对齐第 7 汉字；`-`/`—` 渲染为 `——`，`•` 归一为 `·`。表内文字（含表头与合并单元格）居中编排（GBT-B09）；表题居中置于表上方。编号连续性（章/条/列项/附录字母不跳号、不重复）由合规层规则 GBT-H03/C14/C15 校验并记录缺失编号；编号中的 O/I/l 字形混淆由 GBT-C16 校验。标准文档末尾渲染终结线（末页居中粗实线，长度=版心宽度四分之一）。

当 Markdown 的自动有序列表无法保留原始 `a)`/`1)` 标记时，必须按上例作为普通段落逐行写入，并在其前加机器注释：

```markdown
<!-- ssir:list style="alpha-paren" level="1" -->
a) 第一项；
b) 第二项。
```

### 6.3 规范性引用文件和参考文献

`## 2 规范性引用文件` 的内容使用无序列表，每项保留标准号、日期、名称和括号中的采用信息的原始文本：

```markdown
## 2 规范性引用文件

下列文件中的内容通过文中的规范性引用而构成本文件必不可少的条款。

- GB/T 755-2025 旋转电机 定额和性能
- GB/T 2423.17-2008 电工电子产品环境试验 第2部分：试验方法 试验：盐雾
```

正文中的内部或外部引用不使用自创链接替代原始文字。允许补充链接，但必须保留可见的原始引用文本。

### 6.4 表

表题必须位于表格前一行，格式为 `**表<编号> <表题>**`。表格必须使用 GFM pipe table，包含表头分隔行；单元格内的换行使用 `<br>`，竖线使用 `\\|` 转义。

```markdown
<!-- ssir:table id="tbl-001" header-rows="1" -->
**表1 定额**

| 序号 | 型号 | 额定功率（kW） |
|------|------|----------------|
| 1 | BS11 | 11 |
| 2 | BS15 | 15 |

> 注：表中空白单元格表示该项未规定。
```

规则如下：

- 表号和表题必须完整保留，表号可以是 `1`、`A.1` 等原始形式。
- 不得通过省略空单元格来缩短行；每一行必须具有与表头相同的列数。
- 合并单元格无法由 GFM 原生表达时，表格必须保留展开后的单元格文本，并在表格注释后紧接写入合并指令：

```markdown
<!-- ssir:table id="tbl-002" header-rows="2" -->
**表2 示例**

| 项目 | 条件 | 值 |
|------|------|----|
| 温度 | 高温 | 40 |
| 温度 | 低温 | -20 |

<!-- ssir:table-merge table="tbl-002" row="1" column="1" rowspan="2" colspan="1" -->
```

- `row` 为 0-based 表格行（不含 GFM 分隔行）：`row=0` 表示表头行（`header-rows=1` 时），数据行从 `1` 开始；`column` 从 1 开始。表头行与数据行的合并单元格均可表达（表头跨列如“功率因数cosφ 跨两列”用 `row=0`）。若合并信息不可得，禁止臆造，导入器应记录 `preservationStatus=partial`。

### 6.5 图和图占位

有图片资产时，使用图片语法，图片替代文本必须包含图号和图题：

```markdown
<!-- ssir:figure id="fig-001" -->
![图1 电气性能测试线路图](assets/fig-001.png)
```

没有可交付图片资产时，必须使用标准占位块，不得省略该图：

```markdown
<!-- ssir:figure id="fig-001" asset-status="missing" -->
> [图1 电气性能测试线路图（图片占位）]
```

- `fig-001` 必须与 sidecar 中的资产/区域映射一致。
- 图题应保留在替代文本或占位文本中，不能只保留文件名。
- 同一图的题注不得在图片后再复制一次；若原文题注与替代文本不同，使用 `caption="..."` 属性显式提供原文。

### 6.6 数学公式

可使用 LaTeX 的公式采用显示公式块，后接原始公式编号：

```markdown
<!-- ssir:formula id="fm-001" -->
$$
U = R I
$$
式（1）
```

无法可靠转换为 LaTeX 的公式必须保留原始表示：

````markdown
<!-- ssir:formula id="fm-002" format="raw" -->
```formula
U_N = U_0 / sqrt(3)
```
式（2）
````

不得将公式转换为自然语言描述，也不得删除公式编号。

### 6.7 注、示例、警示和脚注

注、示例和警示使用 block quote，前缀必须明确：

```markdown
> 注：在不引起混淆的情况下，本文件中的“电动机”简称为“电机”。

> 示例：额定电压为 24 V 的产品属于低压直流电机。

> 警示：试验前应确认设备已可靠接地。
```

多条注使用 `注1：`、`注2：`。脚注使用 GFM 脚注语法：

```markdown
额定电压见表1。[^1]

[^1]: 电压单位为 V。
```

### 6.8 无法分类或原样保留内容

任何不能归入上述类型的内容必须放入 `unknown` 指令和代码块，代码块内逐字保留原始文本：

````markdown
<!-- ssir:unknown id="unk-001" type-hint="layout-fragment" -->
```text
[原 PDF 中无法确定归属的页眉片段]
```
````

用户不得用 `unknown` 指令隐藏本可正常表达的正文、表格或图；解析器会对此发出质量警告。

## 7. 稳定块 ID 和 Markdown 源映射

CSMParser 按 AST 顺序为每个结构或内容块生成稳定 block ID。为使 MinerU 路径可复现，生成器应在块前写入 `<!-- ssir:block id="..." -->`。示例：

```markdown
<!-- ssir:block id="h-004" -->
## 4 技术要求

<!-- ssir:block id="p-017" -->
电动机应符合本文件的要求。
```

用户输入可以不提供这些注释。导入器必须使用规范化后的 AST 路径生成 ID，例如 `md:heading:4`、`md:paragraph:17`，并在转换报告中标记 `blockIdsGenerated=true`。一旦系统输出 CSM，后续编辑应保留已生成的 ID；修改内容后必须重新校验 sidecar hash。

## 8. 禁止写法

以下写法不符合 CSM：

| 禁止项 | 原因 | 正确方式 |
|--------|------|----------|
| 用 `## 4.1` 表示章、用 `### 4` 表示条 | 标题深度与编号层次倒置 | 按第 5.2 节映射 |
| 只写 `表1` 而没有表题或表格 | 无法建立完整 Table | 表题 + GFM 表格 |
| 用截图替代表格正文 | 单元格内容不可提取 | 写出 GFM 表格，截图作为附加资产 |
| 删除无法识别的页眉、公式或图 | 破坏源保真 | 使用 `unknown`、公式原文或图占位 |
| 将 `应` 改为 `宜`、改变数值/单位/比较符 | 造成语义变更 | 保持原文 |
| 用 Markdown 链接文本替代标准号或条款号 | 丢失 rawTarget | 可增加链接，但保留可见原文 |
| 在正文使用未定义 HTML | 解析结果不稳定 | 使用规范 Markdown 或 `ssir` 指令 |

## 9. 规范化规则

CSMNormalizer 仅可执行以下无语义损失的规范化：

- 将行尾统一为 LF，移除 BOM；
- 将相邻块间空行规范为一个；
- 统一 GFM 表格分隔行中的对齐短横线数量；
- 对标题、图片、表格、公式、unknown 块补充缺失的稳定 block ID；
- 将允许的软换行合并为单个空格。

以下变化必须拒绝或作为人工审核项：

- 章节/条款/附录编号变化；
- 规范性动词、禁止性表述、数值、单位、比较运算符变化；
- 表格单元格、公式原文、图题、引用原文变化；
- 删除未识别内容、图占位或表格合并元数据；
- 将带 sidecar 的 CSM 正文修改后继续使用旧 sidecar。

## 10. Provenance Sidecar

当 CSM 由 MinerU 从 PDF 生成，或用户需要声明 PDF 级可追溯时，必须提供同名 sidecar：

```text
Q_EXAMPLE_001-2026.ssir.md
Q_EXAMPLE_001-2026.provenance.json
```

sidecar 使用 UTF-8 JSON，最小格式如下：

```json
{
  "provenanceVersion": "1.0",
  "markdownFile": "Q_EXAMPLE_001-2026.ssir.md",
  "markdownSha256": "<sha256-of-exact-markdown-bytes>",
  "sourceFiles": [
    {
      "id": "src:0123456789abcdef",
      "fileName": "Q_EXAMPLE_001-2026.pdf",
      "mimeType": "application/pdf",
      "sha256": "<source-pdf-sha256>"
    }
  ],
  "blocks": [
    {
      "blockId": "p-017",
      "markdown": { "startLine": 42, "endLine": 42 },
      "sources": [
        {
          "sourceFileId": "src:0123456789abcdef",
          "sourceBlockId": "mineru:block:0017",
          "pdfPageIndex": 3,
          "documentPageLabel": "2",
          "bbox": [72, 120, 540, 160],
          "textQuote": "电动机应符合本文件的要求。"
        }
      ]
    }
  ]
}
```

规则如下：

- `markdownSha256` 必须与 CSM 的精确字节内容匹配；不匹配时不得使用 sidecar 生成 PDF 锚点。
- 一个 CSM block 可以映射到多个 PDF 区域，例如跨页表格；所有映射都应保留。
- 用户 CSM 可以提交自身系统生成的 sidecar；来源可以是 PDF、DOCX 或其他受支持文件，但 `mimeType` 和定位字段必须如实声明。
- 未提供或失效 sidecar 时，解析器必须保留 Markdown 行/列锚点，并把 PDF 级锚点标记为不可用，而不是伪造坐标。

## 11. 导入校验清单

在 CSM -> SSIR 前，导入器必须执行以下校验：

1. 文件编码、front matter、`csm-version` 和必填元数据有效。
2. 仅有一个 H1，且与 front matter `title` 一致。
3. 正文章/条编号连续、层级与标题深度一致，附录标识合法。
4. 表格列数一致；表题、图题、公式编号、注/示例/警示前缀符合本规范。
5. 所有 `ssir` 指令语法正确，ID 不重复，引用的表/图 ID 存在。
6. `unknown`、图占位和原始公式都已保留，而非为空内容。
7. sidecar 存在时，文件名、哈希、block ID 和行号映射有效。
8. 输出 Extraction IR 后，所有正文块都有 Markdown 行/列和 block ID；有有效 sidecar 的块还应具有相应 PDF SourceAnchor。
9. 当 `extensions.standard-profile: product` 存在时，执行第 5.4 节的产品标准检查，并将不确定项写入质量评估，不得静默修正。

默认导入将诊断分为以下三类，并为每项写入独立的转换报告：

| 类别 | 默认行为 | 典型情况 |
|------|----------|----------|
| 可修复格式问题 | 内存修复后继续 | BOM/CRLF、缺少 `extensions` 或 `source`、缺少语言或标识、短表格行、缺少对象 ID |
| 可保留质量问题 | 原样转换，`QualityAssessment.overallStatus=partial` | H1 与元数据标题不一致、章节跳号、未知指令、图资产缺失、标准号或产品标准编写提示 |
| 不可接受错误 | 拒绝导入，不写 SSIR | 非 UTF-8、无法定位/解析 YAML front matter、未闭合公式或代码围栏、重复显式 ID、无法安全确定表格列结构、生成后的 SSIR Schema/语义校验失败 |

GB/T 1.1 和 GB/T 20001.10 中按适用情况设置的组成部分，例如目次、引言、规范性引用文件、术语和定义、分类/标记/编码、取样、试验方法、检验规则、标志标签、包装运输贮存、附录、参考文献和索引，缺失时不得单独阻断导入。产品标准仅对可识别的“范围”“技术要求”等基础要素作质量提示；提示不改变原文。

## 12. 用户可复制模板

完整可复制模板保存于 `corpus/golden/SSIR_CANONICAL_MARKDOWN_TEMPLATE.md`。用户应从该模板开始准备数据，不应直接以现有非 CSM Markdown 示例作为输入契约。

## 13. 版本兼容

- CSMParser 必须根据 `csm-version` 选择对应解析器；默认导入对缺失或未知版本以当前兼容模式解析并记录报告，`--strict` 必须拒绝。
- 后续新增可选字段、可选 `ssir` 指令或 sidecar 属性属于兼容性小版本更新。
- 删除字段、改变标题层级映射、改变表格/图/公式语义属于不兼容主版本更新。
