## 引言
随着标准数字化转型需求提升，各类标准管理、检索、比对、智能解读系统需要统一、可机器解析的标准文档结构化模型。
现有文档格式（Word、PDF）侧重可视化排版，缺乏标准化语义描述，无法支撑自动化数据抽取与跨平台互通。

本文件构建三维度全文元模型，统一定义标准文档语义结构，实现：
1. 标准内容计算机可识别、可拆解、可索引；
2. 不同机构、不同系统间标准结构化数据互通；
3. 支撑标准智能检索、条款比对、合规自动审查等数字化应用。

本文件仅定义**语义元模型**，不绑定具体存储/交换格式，可映射至XML、JSON、RDF等任意结构化载体。

# 1 范围
本文件从三个维度描述标准文档结构化的全文元模型：层次元模型、要素表述形式元模型、内容要素元模型；规定各维度模型元素、属性及相互关联规则。

本文件适用于各类国家标准、行业标准、地方标准、团体标准、企业标准的文档结构化信息化开发、数据库建库、数据交换、智能解析系统建设。

本文件不适用于仅扫描图片、无文本图层的纯图像版标准扫描件。

# 3 术语和定义
下列术语和定义适用于本文件。
## 3.1
元模型 metamodel
描述一类文档/数据结构的抽象模型，定义对象类型、属性、关联关系，用于约束实例数据结构。

## 3.2
层次元模型 hierarchy metamodel
描述标准文档自上而下嵌套层级关系的模型，定义文档、分块、章、条、段等容器层级结构。

## 3.3
要素表述形式元模型 presentation metamodel
描述内容载体表现形态的模型，区分纯文本、列表、表格、图、公式等排版形态。

## 3.4
内容要素元模型 semantic metamodel
描述条款业务语义类型的模型，区分范围、规范性要求、试验方法、术语定义等业务语义要素。

## 3.5
元素 element
元模型中定义的独立对象节点，包含唯一标识、属性集、子元素关联。

## 3.6
属性 attribute
描述元素特征的键值对，分为必选/可选、单值/多值，绑定固定数据类型与约束。

# 5 全文元模型
## 5.1 概述
全文元模型由**三类正交维度元模型**组成，任意一段标准内容同时归属三层模型：
1. 层次维度：定位内容在文档嵌套树中的位置（文档→前言→第5章→5.2条→段）；
2. 表述形式维度：定义内容载体形态（普通段落/有序列表/三线表/矢量图）；
3. 内容语义维度：定义内容业务类型（规范性要求/试验步骤/术语定义/资料性注释）。

三层模型独立解耦、通过唯一内容ID建立关联，互不覆盖、可单独扩展。

## 5.2 层次元模型
层次元模型为树形嵌套结构，自上而下层级顺序：
1. 标准文档（根节点，唯一）
2. 文档分块：封面、目次、前言、引言、正文、附录、参考文献、索引
3. 章节层级：章→条→款→项→子项（遵循GB/T 1.1章节编号规则）
4. 正文内容容器：段落、列表容器、表格容器、图容器、公式容器

约束规则：
- 所有正文内容必须挂载在最底层内容容器下；
- 附录区分规范性附录、资料性附录，层级逻辑与正文一致；
- 分块不可交叉嵌套，一章仅属于一个分块。

## 5.3 要素表述形式元模型
按内容可视化载体分为四大类：
1. **基础文本类**：普通段落、标题文本、注释文本、引用文本、脚注；
2. **列表类**：有序列表、无序列表、复合多层列表；
3. **表格类**：简单表、复合表头表、分栏表、注表；
4. **图形公式类**：矢量图、位图、数学公式、化学结构式。

同一层次节点下可混合多种表述形式元素，通过`presentationType`字段区分类型。

## 5.4 内容要素元模型
按标准业务语义分为四大类语义要素：
1. **标识类要素**：标准编号、中英文名称、发布/实施日期、归口单位、版本信息；
2. **说明类要素**：范围、规范性引用文件、术语定义、符号说明、资料性概述；
3. **规范性技术要素**：要求、试验方法、检验规则、标志、包装、运输、储存；
4. **补充附属要素**：注释、附录说明、参考文献、示例、警示提示。

每个最小内容容器必须绑定唯一语义要素类型，用于机器自动识别条款用途。

## 5.5 三类元模型关联关系
1. 同一最小内容实例拥有三套独立属性：层级属性、表述形式属性、语义属性；
2. 通过全局唯一`contentGlobalId`作为外键统一关联三层模型；
3. 层级模型控制嵌套父子关系，表述与语义模型不参与嵌套，仅为内容打标签；
4. 扩展规则：新增表述/语义类型仅需扩展枚举值，不改动层级树结构。

# 6 元模型元素属性通用规则
## 6.1 属性分类
1. 标识属性：id、globalId、parentId、sortOrder（排序序号）；
2. 元数据属性：createTime、sourceFile、pageNum（原PDF页码）；
3. 业务特征属性：type、normativeFlag（是否规范性）、appendixKind（附录类型）；
4. 内容存储属性：textContent、tableCells、graphUri、formulaLatex。

## 6.2 属性数据类型
- 字符串String：文本、名称、URI、编号；
- 布尔Boolean：true/false（如是否规范性）；
- 整数Integer：页码、排序号、行数、列数；
- 枚举Enum：限定固定取值集合（分块类型、语义类型、表格类型）；
- 数组Array：多值属性（多个起草单位、多个引用文件）；
- 嵌套对象Object：复合结构（表格单元格、列表项）。

## 6.3 属性约束
1. 必选(M)属性实例中不得缺失，空字符串视为无效；
2. 枚举属性仅允许附录B规定值，不支持自定义文本；
3. 排序号sortOrder在同一父节点下连续不重复，用于还原原文排版顺序；
4. URI类属性需符合RFC 3986规范，外部资源需带访问地址；
5. 页码pageNum对应原始PDF页码，无原图时允许为空（OCR纯文本场景）。

# 7 层次元模型元素及属性
## 7.1 根元素：标准文档 StandardDocument

## 7.2 文档分块元素 DocumentBlock
分块枚举值：cover、toc、foreword、introduction、mainBody、normAppendix、infoAppendix、reference、index
| 属性名 | 约束 | 类型 |
|--------|------|------|
| blockId | M | String |
| blockType | M | Enum |
| sortOrder | M | Integer |
| childChapterList | O | Array[Chapter] |

## 7.3 章节层级元素（Chapter/Clause/SubClause/Item）
通用公共属性：
- level：层级深度（章=1，条=2，款=3，项=4）
- number：编号字符串（5、5.2、5.2.1、a）
- title：章节标题文本
- normativeFlag：Boolean，true=规范性内容
- childContentList：下属内容容器集合

## 7.4 正文内容容器元素 ContentContainer
所有可见文本、表格、图、公式的承载节点，层次树叶子节点。
核心属性：
- contentGlobalId：全局唯一关联ID（三层模型关联主键）
- pageNum：原始PDF页码
- sortOrder：同章节内显示顺序
- presentationRef：关联表述形式元素ID
- semanticRef：关联语义要素元素ID

# 8 要素表述形式元模型元素及属性
## 8.1 基础文本类 TextBlock
type枚举：para、heading、note、footnote、quote
- textContent：完整文本字符串
- styleMark：格式标记（加粗、斜体、下标、上标数组）

## 8.2 列表类 ListBlock
type：ordered有序 / unordered无序
- itemList：列表项数组，每项包含itemText、subList（子列表递归）

## 8.3 表格类 TableBlock
- rowCount、colCount：行列数
- cellMatrix：二维单元格数组，单元格包含text、colspan、rowspan、cellNote
- tableNote：表注文本数组

## 8.4 图形公式类 GraphFormulaBlock
- resourceType：graph矢量图 / bitmap位图 / formula数学公式
- resourceUri：资源文件链接
- altText：图题、公式说明文本
- latexContent：公式LaTeX源码（仅公式类型）

# 9 内容要素元模型元素及属性
## 9.1 标识类 IdentifySemantic
语义类型：stdBasicInfo、draftOrgList、drafterList
存储标准基础元数据集合。

## 9.2 说明类 ExplanationSemantic
类型：scope、normRefFile、termDefine、symbolExplain、generalIntro

## 9.3 规范性技术类 NormTechSemantic
类型：requirement、testMethod、inspectRule、markDemand、packTransportStorage
标记强制/推荐/可选技术条款。

## 9.4 补充附属类 SupplementSemantic
类型：example、warning、noteExplain、appendixExplain、bibliographyItem
